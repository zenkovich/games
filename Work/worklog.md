### Проблемы и решения
1. **Класс компонента не находился.** `class X extends o2.Component` — лексическая привязка, не
   свойство глобала; загрузчик ищет `GetOwnProperty(className)`. Решение: `var SpaceEvolver = class ...`.
2. **`img.SetDrawingDepth` — не функция.** Глубина отрисовки живёт на `Actor` (он `ISceneDrawable`),
   а `ImageComponent` наследует только `Component` + `Sprite`. Решение: `actor.SetDrawingDepth(...)`.
3. **`actor.transform` / `widget.layout` undefined в JS.** Публичные поля-указатели не биндятся;
   для скриптинга есть `GetTransform()` и `GetLayout()`. Заменил во всех скриптах.
4. **Пустой кадр (0 draw calls).** Актор, созданный как `NotInScene`, после `AddChild` остаётся вне
   сцены (`IsOnScene()==false`), поэтому не регистрируется в слое как drawable. Решение: создавать
   акторы сразу `new o2.Actor(0)` (InScene). Дополнительно камере задан `drawLayers.SetAllLayers()`,
   `SetFittedSize(540×960)` и pivot (0.5, 0.5), чтобы мир совпал с экраном.
5. **Не рисовался текст.** В проекте нет ассета `ui_style`, поэтому `o2UI.CreateLabel/CreateButton`
   отдают виджеты без слоёв, а дефолтный `Label` ищет несуществующий `stdFont.ttf`. Решение: мост
   собирает `Label`/`Button` вручную из `WidgetLayer` с `Text` на `debugFont.ttf`.
6. **Нет биндингов `Widget::SetTransparency` и `Button::SetCaption`.** Добавил им `@SCRIPTABLE`
   (нужны для затухания цифр урона и цен апгрейдов).
7. **Ангар не исчезал при старте забега.** `OnStart` скриптового компонента приходил дважды →
   второй `Game.Start()` терял ссылку на первый ангар. Решение: guard `_started` в начале `OnStart`.
8. **Сохранённая `Bootstrap.scn` была пустой.** Новые акторы попадают в корневой список сцены только
   на ближайшем `Scene::UpdateAddedEntities()`. Решение: вызывать его перед `o2Scene.Save`.
9. **UI-тест drag'а падал.** `PumpFrames` гонит кадры с минимальной dt, лерп следования не успевал
   сойтись. Решение: `AppTestDriver::Wait(2.0f)` вместо счётчика кадров.

### Геймплейные тесты и найденные баги механики

Владелец сообщил, что «не пропадают ворота». Написал набор геймплейных тестов со скриншотами
(`GameUITests/SpaceEvolverGameplay`) плюс headless-инварианты — они воспроизвели три бага:

1. **Сущности «съедали» соседей при удалении.** `UpdateEnemies` и `UpdateGates` итерировали
   `this.enemies` / `this.gates`, а `DestroyEnemy` / `RemoveGate` внутри цикла делали `splice`
   того же массива. Из-за сдвига индексов следующая сущность пропускалась: она не попадала в
   список `alive` (который затем перезаписывал массив), но её `KillView` не вызывался — спрайт
   оставался висеть на экране навсегда. Это и есть «не пропадающие ворота»: за 40 секунд игры
   на поле накапливалось 6 спрайтов ворот при 2 живых и 3 спрайта врагов при 1 живом.
2. **Двойной лут.** Сплэш от кассетного залпа добивал уже мёртвого врага — монеты и орбы
   начислялись повторно.
3. **Мёртвые оставались целями.** Пули, ракеты и лазер могли наводиться на уже убитую сущность.

Решение: у врагов и ворот появился флаг `dead`; `DestroyEnemy` / `RemoveGate` / `DestroyTargetGate`
идемпотентны, циклы обновления идут по копии массива (`slice()`), а выборка целей
(`FindHitTarget`, `NearestEnemy`, лазер) пропускает мёртвых.

Для тестов добавлен хук `SE.Run.CountViewsByName(part)` — считает живые view-акторы, чтобы
сравнивать число спрайтов с числом живых сущностей. Ещё один биндинг движка: `Label::GetText`
получил `@SCRIPTABLE` (проверка текста HP-плашки).

### WebAssembly: почему не работало

Сборка линковалась, но в браузере игра не поднималась. Две причины, обе — про то, что пакетная
сборка везёт с собой только собранное дерево ассетов:

1. **Мост читал исходную папку `Assets/`.** `o2Assets.GetAssetsPath()` в WASM отдаёт `/Assets/`,
   а в бандл попадает только `/Data/` и `/FrameworkData/` (см. `--preload-file BuiltAssets/WebAssembly@/`).
   Конфиги и JS-модули не находились, `SE.cfg` оставался пустым, игра падала на старте. Теперь
   `LoadConfig` и `RunScript` читают `o2Assets.GetBuiltAssetsPath()`, а `RunScript` ещё и логирует
   отсутствующий модуль вместо тихого пропуска.
2. **Профиль не переживал перезагрузку страницы.** В браузере файловая система — MEMFS, она
   очищается при каждой загрузке, поэтому вся мета-прогрессия терялась. Под `PLATFORM_WASM`
   профиль пишется в `localStorage`, на остальных платформах — по-прежнему в файл.

Ещё `SaveBootstrapSceneIfMissing` теперь не пытается писать сцену там, где исходной папки
`Assets/` нет.

Проверено в реальном Chrome (headless, WebGL2 через SwiftShader) скриптом `Work/wasm_browser_check.py`:
он поднимает http-сервер над `Bin/WebAssembly`, драйвит страницу по CDP, собирает консоль и снимает
скриншоты. Результат: ангар рисуется, START RUN запускает забег с туториалом, покупка апгрейда
сохраняется и переживает перезагрузку (`Work/ScreenShots/w0*.png`), исключений в консоли нет
(единственный 404 — favicon).

Регрессия закрыта headless-тестом `ConfigsAndModulesLoadWithoutTheSourceAssetsFolder`: он через
`SetAssetsPathOverride` подсовывает несуществующую папку исходных ассетов — ровно та ситуация,
что в пакетной сборке.

Порядок сборки WASM (ассеты собираются хостовым инструментом):

```
Bin/Mac/AssetsBuilder -platform WebAssembly -source "$PWD/Assets/" \
    -target "$PWD/BuiltAssets/WebAssembly/Data/" \
    -target-tree "$PWD/BuiltAssets/WebAssembly/Data.json" \
    -compressor-config "$PWD/o2/CompressToolsConfig.json"
cmake --preset wasm && cmake --build --preset wasm -j 8
```
