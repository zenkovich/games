## 2026-08-10 (поздняя ночь) — механика цепочек

Смена кор-механики: слово набирается **цепочкой** — первая буква любая, каждая
следующая обязана быть соседом предыдущей по 8 направлениям; случайно разбросанные
буквы больше не собрать.

- **Выбор** (`ToggleSelect`): проверка соседства с последней буквой; клик по дальней
  плитке — `restart`: начинает новое слово с неё (вью гасит перелёты и запускает
  флаер в нулевой слот).
- **Скоринг**: кластерный бонус потерял смысл (цепочка всегда связна) — удалён;
  вместо него усиленный множитель длины 1+0.5(L−3): 4 буквы ×1.5, 5 ×2 … 8 ×3.5.
- **Спавн**: анти-клин переведён с вертикального правила на соседское — если среди
  заполненных 8-соседей клетки ≥2 букв и нет ни одной гласной, тянется гласная;
  у любой согласной есть гласная рядом → цепочки остаются собираемыми.
- **Подсказка**: `FindBestWord` ищет не мультинабор букв, а **путь-цепочку** (DFS с
  visited, джокер матчит любую букву; старт из клеток первой буквы). Отсев по
  счётчикам букв сохранён. Добавлен фильтр длины `FindBestWord(len)` — для
  length-задач. Пауэрапы/бустеры совместимы с механикой без изменений.
- **Баланс**: цели уровней подобраны по боту — 180/250/350 (бот с идеальной
  подсказкой набирал 253–290 / 351–406 / 466–534 при старых 250/350/500 — впритык;
  человеку нужен запас).
- **Тесты**: переписаны под цепочку и новый скоринг (FarTileRestartsSelection,
  DiagonalChainAllowed, ChainScoreUsesLengthMultiplier и др.); главный новый —
  **BotCanWinEveryCampaignLevel**: бот (первым ходом посеянное слово задания → молоток
  по льду без траты хода → length-задачи словами нужной длины → иначе самое дорогое
  слово-цепочка) выигрывает все 3 уровня на сидах 42/7/2026; в node прогнано 5 сидов
  на уровень — 15/15 побед. Ложная граница в тесте подсказки исправлена (база ФАКТ
  9, а не 11). Все сьюты зелёные.

## 2026-08-10 — доработка по обновлённому ГДД

Обновлённый ГДД добавил: пауэрапы за длинные слова, систему заданий уровней, кампанию
из нескольких уровней. Сопоставил с кодом и доделал недостающее.

### Пауэрапы за длинные слова (бомба/ракета/палочка)
- Модель: `tile.powerup`, `PowerupForLength` (5→бомба, 6→ракета, 7+→палочка); после
  сжигания слова бонус прикрепляется к плитке, занявшей клетку последней буквы.
- Срабатывание при включении плитки-носителя в слово (`_ActivatePowerups`): бомба
  уничтожает 3×3 (очки взорванных букв — плоско в счёт, лёд сносится вместе с плитками);
  ракета крестом и палочка по одинаковым буквам «активируют» плитки — очки в счёт, лёд
  снят, плитки остаются (по ГДД). Взорванные клетки не получают повторный урон льду от
  8-соседства слова (skip-набор `destroyedKeys`).
- Вью: слои-бейджи bomb/rocket/wand на кнопках плиток (LeftTop 30×30), «+N» показывает
  полный `gain` (слово + пауэрапы).
- Спрайты: ключа Gemini в среде нет — нарисовал бейджи программно PIL-скриптом
  `Work/Art/make_powerups.py` в стиле бустеров (круглый бейдж, кремовая заливка,
  коричневый контур), проверил визуально.

### Система заданий и кампания
- Задания в конфиге уровня: `word` (точечное слово, матч с джокерами), `length`
  (N слов из L букв), `powerup` (заработать N бонусов вида), `clearIce` (разбить весь
  лёд; пересчёт и после молотка). Очки — обязательное финальное условие: `_CheckWin` =
  очки ≥ цели И все задания закрыты.
- Сид: `NewGame` выкладывает одно случайное слово из `word`-заданий горизонтально в
  средних рядах (`_SeedWord`); лёд клетки сида обходит.
- Кампания `WordFallConfig.levels` — 3 уровня (КОТ+лёд / ЧАШКА+бомба / РАКЕТА+ракета+лёд);
  `WordFallConfig.level` остался песочницей без заданий для старых тестов.
- UI: панель «ЗАДАЧИ» слева (Task0..4, выполненные зелёные с «+»), «Уровень N» в HUD,
  попап с «ДАЛЬШЕ»/«СНАЧАЛА»/«ЕЩЁ РАЗ» и переходом по уровням. Молоток может закрыть

### Сложности и решения
1. **Strict mode классов**: `WordFall_instance = this` в методе класса кидает ReferenceError
   (тела классов всегда strict). Решение — `globalThis.WordFall_instance = this`.
2. **`GetParent()` возвращает WeakRef** — в JS это непрозрачный объект без методов актора.
   Решение — относительные пути `GetChild("../Board/...")` от актора Game (как в Dragon Defense).
3. **Sliced-кнопки разваливались**: slice border 50px при высоте кнопки 56px. Решение — уменьшил
   исходники (160×104) и slice до 22/24.
4. **CMake GLOB** не подхватывает новые .cpp без реконфига — `cmake --preset mac` перед сборкой.
5. **Первый lookup JS-ассета в headless-тесте возвращал null** — обошёл чтением исходника напрямую
   (`InFile` + `o2Scripts.Parse`), как делает FoxModelTests.
6. Ошибка арифметики в тесте мешка (ожидал 98, в мешке 100) — исправил тест, модель верна.
